# راه‌اندازی کیوسک‌های ورود با چهره

شناسه اتصال از جدول `Devices` در بانک `FoodReservation_API` گرفته می‌شود. هر دستگاه باید URL اختصاصی با `deviceId` داشته باشد؛ این مقدار همان ستون `Id` رکورد است و برنامه مقدار جاری `KioskId` را از آن می‌خواند. برای نمونه رکورد شما با `Id=10002` از مسیر `/Authentication/IndexZP?deviceId=10002` استفاده می‌کند. رکورد نمونه قبلی `Id=8` و `KioskId=853047` دارد.

در IIS این تنظیم‌ها را برای برنامه ثبت کنید:

- متغیر محیطی `ConnectionStrings__KioskRegistry`: رشته اتصال به بانک `FoodReservation_API`؛ رمز را در appsettings یا Git ننویسید.
- متغیر محیطی `FaceLogin__DeviceRecordId`: شناسه رکورد دستگاه (مثلاً `10002`) به‌عنوان مقدار پیش‌فرض.
- برای کیوسک‌های متعدد، URL هر دستگاه را با `deviceId` رکورد خودش باز کنید. لینک ورود با چهره، پارامتر را حفظ می‌کند.

برنامه در هر بار بازشدن صفحه، ستون `KioskId` را از `dbo.Devices` می‌خواند و کوکی محافظت‌شده را خودکار به‌روز می‌کند. بنابراین تغییر `KioskId` در بانک با تازه‌سازی صفحه اعمال می‌شود. حساب بانک API برای برنامه فقط نیاز به دسترسی خواندن جدول `dbo.Devices` دارد.

در کنسول مرورگر، پیام `[Page]` هم `deviceRecordId` و هم `kioskId` را نشان می‌دهد. اگر خطای بازیابی شناسه دیدید، اتصال دیتابیس، دسترسی SELECT، مقدار `deviceId` و مقدار شش‌رقمی `KioskId` همان ردیف را بررسی کنید.
