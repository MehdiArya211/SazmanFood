# کنترل سیاست سهمیه غذا و ثبت خودکار از ورود چهره

## سیاست مرکزی رزرو

آدرس مدیریت: `/Admin/QuotaControl/Index` (فقط مدیر سیستم، RoleId=1).

- پیش‌فرض خاموش است و منطق سهمیه فردی `UnitQuotaPerson` دست‌نخورده می‌ماند.
- روشن: تمام کاربران احرازشده فقط برای روزها و وعده‌های دارای برنامه غذایی می‌توانند رزرو کنند.
- خاموش: هر ثبت جدید و هر درخواست چاپ ژتون از سهمیه فعال همان شخص برای روز و وعده اعتبارسنجی می‌شود.
- روشن/خاموش شدن هیچ سهمیه یا رزرو قبلی را حذف نمی‌کند.
- وضعیت در جدول موجود `Constants` با نوع `FreeFoodReservationEnabled = 7` نگهداری می‌شود؛ Migration لازم نیست.
- تغییرات مدیریت در Logger ثبت می‌شوند.

## ثبت خودکار کاربر از تشخیص چهره

**مهم:** مسیر GET قدیمی `FinalizeFaceLogin?kioskId=...&enrollId=...` از خود مرورگر قابل فراخوانی است و به تنهایی اثبات تشخیص چهره نیست. به همین دلیل برای ایجاد حساب جدید **هرگز** به پارامتر URL اعتماد نمی‌شود. حساب جدید تنها پس از دریافت رویداد امضاشده و یک‌بارمصرف از سرویس معتبر ZP ساخته می‌شود.

### تنظیمات روی سرور

این مقادیر را در environment variables یا User Secrets قرار دهید (کلید واقعی را در Git ثبت نکنید):

```text
FaceLogin__WebhookSecret=<random-high-entropy-secret-at-least-32-characters>
FaceLogin__RequireSignedEvents=true
```

`ApiAddress:KioskId` باید شناسه واقعی دستگاه باشد. مقدار `RequireSignedEvents=true` باعث می‌شود **ورود کاربران قبلی هم فقط بعد از تأیید امضای رویداد** مجاز باشد؛ تا زمانی که سرویس ZP برای ارسال امضا آماده نیست آن را با احتیاط فعال کنید. حساب جدید حتی اگر این گزینه false باشد بدون امضای معتبر ساخته نمی‌شود.

### اتصال سرویس معتبر ZP

پس از احراز موفق چهره در سرور ZP، **پیش از** انتشار `ReceiveAutoLogin` به مرورگر، سرویس ZP باید درخواست زیر را مستقیماً از سمت سرور ارسال کند:

```http
POST /Authentication/RecordVerifiedFace
Content-Type: application/json

{
  "kioskId": 853047,
  "enrollId": 12345678,
  "timestampUtc": 1793800000,
  "nonce": "random-unique-id",
  "signature": "<HMAC-SHA256-Hex>"
}
```

`timestampUtc` زمان واقعی UTC در قالب Unix seconds است (مقدار بالا صرفاً مثال است). رشته امضا دقیقاً عبارت زیر به UTF-8 است:

```text
{kioskId}:{enrollId}:{timestampUtc}:{nonce}
```

امضا باید `HMACSHA256(secret, message)` با کدگذاری hex باشد. سرور زمان را با تلورانس ۳۰ ثانیه بررسی می‌کند، امضا را با مقایسه زمان ثابت می‌سنجد، replay nonce را رد می‌کند و تأیید تشخیص چهره را حداکثر ۴۵ ثانیه نگه می‌دارد. سپس مرورگر با دریافت پیام `ReceiveAutoLogin` به `FinalizeFaceLogin` می‌رود.

در اولین ورود:
1. اگر کاربر قبلاً وجود داشته باشد و فعال باشد، همان حساب استفاده می‌شود.
2. اگر وجود نداشته باشد، **فقط با رویداد تأییدشده** کد پرسنلی به سرویس رسمی پرسنلی ارسال می‌شود.
3. اگر شخص معتبر پیدا شود، حساب با نام کاربری و رمز اولیه کد پرسنلی، نقش رزروکننده غذا و `PasswordIsChanged=false` ساخته می‌شود؛ تکراری ساخته نمی‌شود.
4. نشست تأییدشده چهره می‌تواند وارد پنل شود. ورود بعدی با نام کاربری و رمز، کاربر را تا تغییر رمز اولیه به صفحه تغییر رمز منتقل می‌کند.

### محدودیت‌های عملیاتی مهم

- در معماری فعلی رویداد مرورگر فقط `enrollId` دارد؛ تا وقتی تغییر سمت سرویس ZP برای ارسال webhook انجام نشود، **ساخت امن کاربر جدید از چهره فعال نخواهد شد**.
- اثبات رویداد و nonce فعلاً در `IMemoryCache` همین نمونه وب ذخیره می‌شود. برای چند Web Server / App Pool لازم است از Cache توزیع‌شده و binding مناسب نشست/کیوسک استفاده شود.
- باید ارتباط webhook روی HTTPS و در شبکه محدود با secret قوی باشد؛ هیچ‌گاه secret را به JavaScript یا مرورگر منتقل نکنید.
- این تغییرات، صدور QR یک‌بارمصرف جدید برای تحویل غذا را پیاده‌سازی نکرده‌اند. رسید چاپ مرورگر فقط مدرک رزرو است و جایگزین اسکن تحویل غذا نیست. برای ژتون QR معتبر در سیستم جدید باید شناسه/وضعیت یک‌بارمصرف تحویل به `FoodReserveDetail` یا مدل مخصوص ژتون افزوده شود (Migration و اصلاح TokenScan لازم است).

## بررسی قبل از استقرار

- باز/بستن منوی مدیریت برای مدیر و عدم دسترسی با نقش‌های عادی.
- ثبت آزاد از حساب بدون سهمیه هنگام روشن، و رد همان درخواست پس از خاموش کردن.
- کنترل چاپ برای رزروی که در حالت آزاد ایجاد شده ولی اکنون سهمیه ندارد.
- ساخت امن کاربر از رویداد امضاشده ZP؛ رد URL جعلی و callback با امضای نامعتبر؛ رد nonce تکراری.
- ورود با رمز و الزام تغییر کلمه عبور برای `PasswordIsChanged=false`.
- مقایسه رفتار چاپ فیزیکی مرورگر و چاپ صف سرور روی دستگاه واقعی.
